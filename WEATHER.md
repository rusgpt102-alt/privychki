# Погода обновляется сама

Источник: https://open-meteo.com/. Используется бесплатный API без ключей для личного некоммерческого приложения. Данные Open-Meteo распространяются по CC BY 4.0; ссылка на источник и лицензию есть в карточке. Платные планы не подключены.

Запрашивается погода для центра Екатеринбурга: 56.8389, 60.6057. Геолокация пользователя не запрашивается. Названия привычек и отметки остаются в браузере и в data.json не попадают.

## Как это работает

1. GitHub запускает задание Update weather and publish.
2. fetch.py получает температуру, ощущаемую температуру, ветер, осадки, прогноз на день, восход и закат. Дополнительные библиотеки не нужны.
3. Ответ проверяется, затем data.json заменяется атомарно. updated_at хранит время удачного получения в UTC. Если источник не ответил или ответ неправильный, старый файл и его дата сохраняются. Сбой первого запуска без старого файла завершает задание ошибкой.
4. Задание коммитит только data.json и явно публикует сайт через GitHub Pages Actions. Автоматический коммит сам по себе не запускает новую цепочку заданий.
5. Приложение показывает данные и дату по Екатеринбургу. Оно проверяет файл при открытии, возврате в окно, восстановлении интернета и каждые 15 минут. Данные старше 6 часов помечаются как устаревшие.
6. Service worker версии 3 сначала запрашивает свежий data.json и сохраняет успешный ответ. Без сети показывает последний сохранённый ответ. Если данных ещё нет, появляется понятное сообщение. Привычки работают независимо от погоды.

## Когда обновляется

Каждые 3 часа, на 17-й минуте. Cron в UTC: `17 */3 * * *`.

UTC: 00:17, 03:17, 06:17, 09:17, 12:17, 15:17, 18:17, 21:17.
Екатеринбург, UTC+5: 02:17, 05:17, 08:17, 11:17, 14:17, 17:17, 20:17, 23:17.

Запуск может опоздать на 5–15 минут и дольше. GitHub не гарантирует точное время; при высокой нагрузке отдельные запуски могут быть пропущены.

В публичном репозитории после 60 дней без активности расписание отключается автоматически. Открой Actions → Update weather and publish → Enable workflow, чтобы включить его снова. Регулярные успешные коммиты данных обычно поддерживают активность, но при длительном сбое источника новых коммитов может не быть.

## Как запустить вручную

Открой https://github.com/rusgpt102-alt/privychki/actions/workflows/update.yml → Run workflow → выбери main → Run workflow. Дождись зелёного результата. Открой https://rusgpt102-alt.github.io/privychki/ и проверь строку «Обновлено».

После обновления приложения закрой все открытые вкладки этого сайта и заново открой ссылку. Это позволяет новой версии service worker активироваться. Привычки сохранятся.

## Если погоды нет

Проверь интернет и открой приложение снова. Если данные старые, проверь дату последнего успешного запуска в Actions. Если задание красное, открой его и прочитай ошибку. При недоступном Open-Meteo старые данные остаются, дата успешного обновления не подменяется.
